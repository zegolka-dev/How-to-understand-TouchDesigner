## Суть продукта
Пользователь загружает видео, сделанное в TouchDesigner. Приложение анализирует видео и объясняет, как повторить такой же визуал в TouchDesigner своими руками: какие ноды взять, как их соединить, какие значения параметров поставить. Приложением будут пользоваться друзья автора, у которых нет платного доступа к нейросетям, поэтому всё работает на БЕСПЛАТНЫХ API-ключах самих пользователей.

## Жёсткие ограничения
- Только клиентская часть, БЕЗ собственного бэкенда. Запросы к нейросетям идут напрямую из браузера с ключом пользователя.
- Хостинг: GitHub Pages (статические файлы). Деплой должен работать из корня репозитория или папки /docs; добавь GitHub Actions workflow для деплоя.
- Стек: чистый HTML, CSS и JavaScript (ES-модули), без фреймворков и без сборки. Внешние библиотеки только если без них никак; если нужны, кладём их в репозиторий локально (vendor/) с фиксированной версией, а не подгружаем с CDN.
- Видео НИКУДА не загружается. Кадры извлекаются в браузере через <video> + canvas. В нейросеть уходят только JPEG-кадры (ширина до 768 px, качество ~0.72) и числовые метрики.
- Ключ хранится только в localStorage (в try/catch), есть кнопка «Забыть ключ». Ключ никогда не логируется и не попадает в URL. Всё, что пришло от модели, экранируется перед выводом (защита от XSS). Добавь Content-Security-Policy через meta так, чтобы разрешались только запросы к используемым API.
- Без аналитики и сторонних трекеров. Адаптивная вёрстка (от 360 px).
- Две темы, светлая и тёмная, с переключением (подробности в разделе «Дизайн»).
- Два языка интерфейса и ответов: русский и английский.
- Доступность: видимый фокус, достаточный контраст, aria-label на иконках, управление с клавиатуры.

## Функции
1. **Онбординг при первом запуске** (пошаговый мастер, 4-5 экранов, можно вернуться назад, индикатор прогресса):
   - что делает приложение и что видео не загружается на сервер;
   - как бесплатно получить ключ Google Gemini: открыть aistudio.google.com/apikey, войти через Google-аккаунт, нажать Create API key, скопировать, вставить (кнопка «Открыть страницу» и поле ввода);
   - кнопка «Проверить подключение» (тестовый запрос), понятный результат успех/ошибка с подсказкой, что делать;
   - объяснение бесплатных лимитов простыми словами, без выдуманных цифр: лимиты зависят от тарифа Google и меняются, поэтому нейтральная формулировка и ссылка на актуальные условия;
   - необязательный шаг: запасной провайдер OpenRouter (бесплатные модели с суффиксом :free), такая же пошаговая инструкция получения ключа;
   - мастер можно открыть снова из настроек.
2. **Абстракция провайдеров**: единый интерфейс (analyze, followUp, listModels, testConnection). Реализации: Gemini и OpenRouter. Названия моделей НЕ хардкодь: получай список через API, фильтруй по поддержке изображений, предлагай разумный дефолт (flash-класс для Gemini). При ошибке 429 или исчерпанном лимите предложи переключиться на запасного провайдера и повторить запрос одним кликом.
3. **Структурированный ответ модели**. Просим модель вернуть JSON (для Gemini используй responseMimeType и responseSchema), а интерфейс сам рисует из него результат. Схема: summary, techniques[], nodes[{id, type, family (TOP|CHOP|SOP|DAT|COMP|MAT), params[{name, value, approximate}], purpose}], connections[{from, to, inputIndex}], steps[{n, title, nodeIds, details}], animation[], postfx[], tweakNotes[], uncertainties[], confidence (0-1). Добавь валидацию и мягкое восстановление битого JSON; если не вышло, покажи сырой текст ответа, а не ошибку.
4. **Схема нодов**: из nodes и connections строй SVG-граф слева направо (раскладка по слоям топологической сортировкой, цвета по семействам TOP/CHOP/SOP как в TouchDesigner, подписи с названием и типом, пунктир для неуверенных соединений). Экспорт схемы в SVG и PNG. Клик по ноде подсвечивает соответствующий шаг инструкции и наоборот.
5. **Результат**: разделы «Что на видео», «Использованные приёмы», «Схема нод», «Пошаговая инструкция» (чекбоксы, чтобы отмечать выполненные шаги), «Анимация и управление», «Постобработка», «Что подстроить на глаз». Приблизительные значения помечай значком. Выбор уровня объяснения (новичок / средний / продвинутый) и поле «что особенно интересует».
6. **Экспорт**: Markdown-файл, PDF (через window.print() с отдельным print-CSS, без библиотек), копирование в буфер обмена.
7. **История разборов** в IndexedDB: результат (JSON), миниатюры 3-4 кадров, дата, имя файла, модель. Список, открытие, удаление, «удалить всё», экспорт и импорт истории файлом JSON. Само видео не хранить.
8. **Уточняющие вопросы** к результату (чат с историей; кадры отправляются только в первом сообщении, чтобы экономить лимиты).
9. **Два языка, RU и EN**: переключатель; язык по умолчанию определяется по браузеру. Переводятся интерфейс и ответы модели (язык ответа передаётся в системном промте). Все тексты в словаре i18n, без строк в коде.
10. **Экономия лимитов**: по умолчанию 12 кадров, ползунок 6-24; один запрос на разбор; показывай примерный размер запроса; ограничение длины и размера видео с понятным сообщением.

## Качество системного промта (самое важное для результата)
Вынеси системный промт в отдельный модуль и сделай его сильным:
- роль: опытный TouchDesigner-разработчик и преподаватель;
- обязательно точные названия операторов с типом (Noise TOP, Feedback TOP, Composite TOP, Displace TOP, Level TOP, Geometry COMP, Render TOP, Lfo CHOP и т.д.) и названия параметров как в интерфейсе, стартовые значения, порядок соединений;
- справочник типовых рецептов (feedback-шлейфы, displace-искажения, instancing, калейдоскоп/Mirror/Tile, audio-reactive через Audio Spectrum CHOP, шум и зернистость, bloom/chromatic aberration/glow, GLSL TOP, particles) с признаками, по которым их можно узнать на кадрах;
- правила против выдумывания: если приём нельзя определить по кадрам, писать «вероятно», давать 1-2 варианта и класть это в uncertainties; явно сказать, если видео, возможно, сделано не в TouchDesigner;
- объяснять рабочие выражения (например absTime.seconds*0.2) и как зациклить анимацию;
- не раздувать ответ, только то, что нужно для повторения.

## Дизайн: современный Liquid Glass (в стиле iOS 26)
Интерфейс должен выглядеть как современное приложение Apple с материалом Liquid Glass: полупрозрачные «стеклянные» поверхности, живой фон, плавные пружинные анимации. Нативного glassEffect в вебе нет, поэтому воссоздай эффект средствами CSS и SVG.

**Материал стекла (CSS-токены, не хардкод цветов):**
- backdrop-filter: blur(20-30px) saturate(160-180%) для всех стеклянных поверхностей (карточки, панели, модальные окна, плавающая навигация, кнопки);
- полупрозрачная заливка (светлая тема: белая ~35-55%, тёмная: белая ~6-12%), тонкая внутренняя обводка 1px с градиентной «бликовой» кромкой (ярче сверху-слева), мягкая внешняя тень и inset-тени для объёма;
- большие скругления (карточки 24-28px, кнопки и переключатели в форме капсулы);
- слой блика (specular highlight) через псевдоэлемент с radial/linear-gradient, лёгкий отклик на наведение и нажатие (светлеет, чуть растёт, пружинная анимация);
- по желанию для Chromium: SVG-фильтр feTurbulence + feDisplacementMap для лёгкого эффекта преломления у краёв на крупных элементах; обязательно с fallback без него.

**Фон:** живой цветной фон под стеклом (медленно дрейфующие размытые градиентные пятна, mesh-gradient), чтобы стеклу было что преломлять. Отдельные палитры для светлой и тёмной темы. Анимация фона отключается при prefers-reduced-motion.

**Компоненты в этом стиле:**
- плавающая «пилюля»-навигация (Разбор / История / Настройки), закреплённая сверху или снизу, с выделением активной вкладки скользящим стеклянным «ползунком»;
- сегментированные переключатели (язык, уровень объяснения, тема) со скользящей стеклянной подложкой;
- кнопки: основная (цветное стекло с акцентом), вторичная (прозрачное стекло), иконочные круглые;
- зона загрузки видео как стеклянная панель с анимацией при перетаскивании;
- модальные окна и мастер онбординга как «листы» (sheets) со стеклом, плавное появление со scale и blur;
- ноды в SVG-схеме тоже стеклянные: тонкая светлая обводка, полупрозрачная заливка, цвет-акцент по семейству (TOP, CHOP, SOP и т.д.);
- карточки результата с мягким появлением по очереди (stagger), чекбоксы шагов в стиле iOS-переключателей.

**Две темы с переключателем:**
- светлая и тёмная, переключатель «Авто / Светлая / Тёмная» (Авто следует за prefers-color-scheme) в виде стеклянного сегментированного контрола, доступен из шапки в один клик;
- выбор сохраняется в localStorage (в try/catch);
- применяется атрибутом data-theme на <html> через CSS-переменные; в <head> небольшой инлайн-скрипт выставляет тему ДО отрисовки, чтобы не было мигания;
- плавная смена темы (transition на цвета и фон ~300 мс; View Transitions API только как прогрессивное улучшение);
- обе темы должны выглядеть одинаково продуманно, а не «вторая тема для галочки».

**Читаемость и доступность (не жертвовать ради красоты):**
- текст на стекле должен проходить контраст WCAG AA в обеих темах; для длинного текста (результат разбора, инструкция) используй более плотную заливку стекла;
- fallback: @supports not (backdrop-filter) даёт почти непрозрачные поверхности; при prefers-reduced-transparency и prefers-contrast: more тоже уменьшай прозрачность и усиливай обводки;
- prefers-reduced-motion отключает дрейф фона, пружины и параллакс;
- не вкладывать больше 2 уровней backdrop-filter друг в друга (производительность); в печати (PDF-экспорт) использовать простую белую вёрстку без стекла.

**Типографика и иконки:** системный шрифт (font-family: -apple-system, "SF Pro Display", "Segoe UI Variable", system-ui), чёткая иерархия размеров, умеренный вес шрифтов; иконки в едином линейном стиле, встроенный inline-SVG, без внешних библиотек иконок.
