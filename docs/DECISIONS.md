# Журнал решений

Формат: **решение** — причина.

## Этап 0
- **Корень репо = корень сайта; деплой через GitHub Actions (`upload-pages-artifact` с белым списком файлов), а не «из /docs»** — в `docs/` лежат ТЗ и журнал, их не нужно публиковать; так же исключаются prototype/, tests/.
- **Никаких внешних библиотек (vendor/ пуст)** — Markdown-рендер, SVG-граф, иконки, PNG-экспорт делаются вручную; меньше поверхности для XSS и обновлений.
- **Инлайн-скрипт темы в `<head>` разрешён через CSP-хэш `sha256-…`** — нужен для отсутствия мигания, при этом `unsafe-inline` не включаем. Хэш пересчитывается при правке скрипта, тест сверяет.
- **Ключ Gemini передаётся в заголовке `x-goog-api-key`, не в `?key=`** — ключ никогда не попадает в URL (как в прототипе).
- **testConnection = ListModels (+ `GET /key` для OpenRouter), без генерации** — не тратит квоту генерации и проверяет ключ.
- **Модели не хардкодятся**: Gemini — фильтр `generateContent` + `^gemini` минус спец-модели (логика прототипа), сортировка flash → flash-lite → pro; OpenRouter — `:free` + `input_modalities ∋ image`.
- **Переключение на запасного провайдера — только по клику пользователя** — ТЗ: «предложи… одним кликом»; не тратим чужие лимиты без спроса.
- **Схема ответа расширена: `techniques[]` = `{name, why}`, `connections[].uncertain`, `isLikelyTouchDesigner`** — пунктир для неуверенных соединений и предупреждение «возможно не TD» требуют явных полей; normalize принимает и строки в techniques.
- **Обратные рёбра (feedback-циклы) исключаются из топосортировки и рисуются отдельной дугой** — иначе раскладка по слоям невозможна, а feedback — частый приём.
- **Уточняющие вопросы из открытой истории идут без кадров (результат JSON + метрики текстом)** — видео и полные кадры не хранятся по ТЗ.
- **Ответы на уточняющие вопросы — Markdown, а не JSON** — это свободный диалог; рендер через экранирующий md() из прототипа.
- **Шрифт системный, палитра своя (а не из рекомендаций скилла: Cormorant/Montserrat, золото)** — ТЗ требует системный шрифт без внешних загрузок; рекомендации скилла взяты в части правил Liquid Glass (стекло на навигации/контролах, плотный слой под длинным текстом, reduced-transparency/motion).
- **Ноды графа — «стекло» без backdrop-filter (полупрозрачная заливка + кромка)** — ограничение ≤2 уровней вложенного blur и производительность.
- **Лимиты видео: ≤10 мин и ≤500 МБ** — видео не уходит в сеть; ограничение ради памяти и времени seek. Можно поменять в `video/limits.js`.
- **Тесты на Playwright как devDependency в package.json** — приложение без сборки; package.json только для тестов.
