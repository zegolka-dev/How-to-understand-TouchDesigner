# Журнал решений

Формат: **решение** — причина.

## Этап 0
- **Корень репо = корень сайта; деплой через GitHub Actions (`upload-pages-artifact` с белым списком файлов), а не «из /docs»** — в `docs/` лежат ТЗ и журнал, их не нужно публиковать; так же исключаются prototype/, tests/.
- **Никаких внешних библиотек (vendor/ пуст)** — Markdown-рендер, SVG-граф, иконки, PNG-экспорт делаются вручную; меньше поверхности для XSS и обновлений.
- **Инлайн-скрипт темы в `<head>` разрешён через CSP-хэш `sha256-…`** — нужен для отсутствия мигания, при этом `unsafe-inline` не включаем. Хэш пересчитывается при правке скрипта, тест сверяет.
- **Ключ Gemini передаётся в заголовке `x-goog-api-key`, не в `?key=`** — ключ никогда не попадает в URL (как в прототипе).
- **testConnection = ListModels (+ `GET /key` для OpenRouter), без генерации** — не тратит квоту генерации и проверяет ключ.
- **Модели не хардкодятся**: Gemini — фильтр `generateContent` + `^gemini` минус спец-модели (логика прототипа), сортировка flash → flash-lite → pro; OpenRouter — `:free` + `input_modalities ∋ image`.
- **Переключение на запасного провайдера — только по клику пользователя** — ТЗ: «предложи… одним кликом»; не тратим чужие лимиты без спроса.
- **Схема ответа расширена: `techniques[]` = `{name, why}`, `connections[].uncertain`, `isLikelyTouchDesigner`** — пунктир для неуверенных соединений и предупреждение «возможно не TD» требуют явных полей; normalize принимает и строки в techniques.
- **Обратные рёбра (feedback-циклы) исключаются из топосортировки и рисуются отдельной дугой** — иначе раскладка по слоям невозможна, а feedback — частый приём.
- **Уточняющие вопросы из открытой истории идут без кадров (результат JSON + метрики текстом)** — видео и полные кадры не хранятся по ТЗ.
- **Ответы на уточняющие вопросы — Markdown, а не JSON** — это свободный диалог; рендер через экранирующий md() из прототипа.
- **Шрифт системный, палитра своя (а не из рекомендаций скилла: Cormorant/Montserrat, золото)** — ТЗ требует системный шрифт без внешних загрузок; рекомендации скилла взяты в части правил Liquid Glass (стекло на навигации/контролах, плотный слой под длинным текстом, reduced-transparency/motion).
- **Ноды графа — «стекло» без backdrop-filter (полупрозрачная заливка + кромка)** — ограничение ≤2 уровней вложенного blur и производительность.
- **Лимиты видео: ≤10 мин и ≤500 МБ** — видео не уходит в сеть; ограничение ради памяти и времени seek. Можно поменять в `video/limits.js`.
- **Тесты на Playwright как devDependency в package.json** — приложение без сборки; package.json только для тестов.

## Этап 1
- **View Transitions для смены темы с таймаутом 700 мс (skipTransition + прямое применение)** — в фоновой/неотрисовываемой вкладке переход «зависает» и перехватывает клики.
- **Спрайт иконок встроен в index.html, а не отдельным файлом** — нет лишнего запроса и проблем с `<use>` внешних файлов.
- **Пятна фона — radial-gradient без `filter: blur`** — дешевле для GPU, вид тот же.
- **`tools/csp-hash.mjs`** — пересчёт/проверка sha256 инлайн-скрипта темы в CSP.

## Этап 2
- **Провайдер реализует низкоуровневый `generate()` в нейтральном формате; `analyze/followUp/listModels/testConnection` — через registry + ai/** — промт и схема одни на всех, провайдеры отличаются только транспортом.
- **Закрытие мастера крестиком тоже помечает онбординг пройденным** — чтобы не навязывать его; открывается снова из настроек.
- **Бейдж провайдера показывает «используется / запасной / не настроен» по факту, а активный провайдер выбирается переключателем в настройках.**

## Этап 3
- **Системный промт один, на английском, с директивой языка ответа** (вместо двух копий RU/EN) — модели надёжнее следуют английским инструкциям, названия операторов TD всё равно английские; язык строк JSON задаётся явно.
- **analyze/followUp вынесены в `js/ai/service.js`** (а не в registry) — registry не зависит от промта/схемы.
- **maxOutputTokens 16384 для разбора** — у «думающих» flash-моделей размышления съедают бюджет вывода, 8192 могло обрезать JSON.
- **Миниатюры через `img.onload`, а не `decode()`** — `decode()` не завершается во фоновой вкладке.

## Этап 4
- **Параметры нод показываются внутри шагов; ноды без шага — в свёрнутом блоке под схемой** — не дублируем таблицы.
- **Экспорт SVG/PNG подставляет вычисленные стили и фон темы** — CSS-переменные вне страницы не работают.
- **ffmpeg-static не используем**: npm блокирует его install-скрипт (скачивание бинарника). `tests/fixtures/make-video.mjs` берёт ffmpeg из PATH, иначе тесты генерируют webm через canvas+MediaRecorder в headless Chromium.
- **Playwright начат в этапе 4** (раньше плана) — встроенная панель браузера скрыта и не рендерит canvas/видео, проверять нужно в headless.
- **Markdown: код-спаны обрабатываются отдельно** — `*` в выражениях (`seconds*3`) не превращаются в курсив.

## Этап 5
- **Контекст для вопросов из истории: user-ход с метриками и JSON разбора + короткий model-ход «OK»** — роли чередуются, кадров нет.
- **Сохранение изменений записи без debounce, через последовательную очередь** — debounce терял отметки шагов при быстром экспорте/закрытии.
- **Импорт: записи прогоняются через clean()+normalize, конфликт id → новый id** — защищает от чужих/вредоносных файлов.

## Этап 6
- **Контраст проверяется расчётом по токенам** (плотное стекло поверх фона и каждого цветного пятна, все три уровня текста) — устойчивее, чем пиксельный анализ скриншотов.
- **Тест «нет мигания»: main.js задерживается через route, тема проверяется до его загрузки.**
- **CI деплоя проверяет CSP-хэш** — устаревший хэш сломал бы тему на проде.

## После релиза
- **503 «high demand»: один автоповтор через 2,5 с, затем кнопка «Попробовать модель X» (следующая из списка) и запасной провайдер** — самая новая flash-модель бывает перегружена; пользователь не должен сам искать другую модель в настройках.
- **Автоматическая цепочка моделей: при 503/429/404/пустом ответе пробуем до 3 моделей того же провайдера, рабочая запоминается** — у тестеров перегружены были именно новые flash-модели, ручной перебор пугает. На другого провайдера автоматически не переключаемся (чужие лимиты — только по клику).
- **При лимите показываем текст ошибки от API** — видно, дневной это лимит или временный (OpenRouter upstream).
- **Переключатель провайдера и выбор модели прямо на экране разбора** — после «Переключиться на OpenRouter» не было быстрого пути назад к Gemini.
- **Поле `observations` первым в схеме + шкала уверенности в промте** — модель сначала фиксирует, что видит, потом подбирает приёмы (лучше разбор); без якорей она занижала confidence до ~0.5.
- **Предупреждение о слабых моделях (OpenRouter free, flash-lite)** — тестеры получали плохие разборы, не понимая причину.

## Фидбек тестера (2026-10-01)
- **Минимальная сеть: каждая нода обоснована наблюдением, лимит нод по уровню (3–6 / 4–9 / до 12)** — тестер: «добавил кучу ненужных нод».
- **connections.kind = wire | reference; провод между разными семействами автоматически становится ссылкой** — в TD CHOP→параметр и Target TOP не провода; модель рисовала их проводами и путала.
- **Ноды в стиле TD: шапка цвета семейства с типом, пронумерованные входы, номер шага; ссылки — пунктир сверху в ноду.**
- **«База видео преподавателей» реализована как раздел «Уроки по теме» с поисковыми ссылками YouTube (tutorialQueries от модели)** — без сервера нельзя хранить/индексировать чужие видео; поиск не выдумывает ссылки.
- **Светлые цвета семейств затемнены** — белая подпись в шапке ноды должна проходить AA.
